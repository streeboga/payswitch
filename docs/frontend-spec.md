# ТЗ: Личный кабинет Payswitch

## 1. Общее

**Тип приложения:** Standalone React SPA (отдельное приложение, НЕ Inertia)
**Связь с бэкендом:** REST JSON:API v1.1 (`/api/v1/`)
**Стек:** React 19, TypeScript 5.7, TanStack Router, TanStack Query, Tailwind CSS 4, Radix UI
**Язык интерфейса:** Русский
**Тема:** Light / Dark
**Сборка:** Vite 7
**Деплой:** Отдельно от Laravel-бэкенда (статика на CDN или отдельный домен)

---

## 2. Архитектура приложения

### 2.2 Структура проекта

```
src/
├── api/                  # API-клиент, эндпоинты, типы ответов
│   ├── client.ts         # Базовый HTTP-клиент с auth-хедерами
│   ├── endpoints/        # По одному файлу на ресурс (payments.ts, merchants.ts, ...)
│   └── types/            # TypeScript-типы из JSON:API ответов
├── app/                  # Корневой layout, providers, router
├── components/           # Переиспользуемые UI-компоненты
│   ├── ui/               # Radix UI primitives (button, dialog, badge, ...)
│   ├── data-table/       # Универсальная таблица с фильтрами, сортировкой, пагинацией
│   ├── context-switcher/ # Org → Merchant → Profile переключатель
│   └── shared/           # StatusBadge, CopyButton, JsonViewer, MoneyFormat, ...
├── hooks/                # Кастомные хуки (useCurrentContext, useAuth, ...)
├── pages/                # Страницы (по роуту)
├── stores/               # Zustand stores (context, auth, preferences)
└── lib/                  # Утилиты (formatMoney, formatDate, ...)
```

### 2.3 Аутентификация

Пользователь логинится через Laravel Fortify (session-based) или через API-ключ. Два варианта:

**Вариант A — Session auth (рекомендуемый для dashboard):**
- SPA на том же домене (или с CORS), использует Laravel Sanctum SPA-аутентификацию
- `POST /login`, CSRF-токен, session cookie
- Поддержка 2FA через существующий Fortify flow

**Вариант B — API Key auth:**
- Пользователь вводит API-ключ, хранится в `localStorage`
- Передаётся в хедере `X-API-Key` / `X-Secret-Key`

### 2.4 Глобальный контекст (мультитенантность)

Центральная концепция дашборда — **трёхуровневый контекст**:

```
Organization → Merchant Account → Business Profile
```

**Хранение:** Zustand store + `localStorage` (persist между сессиями).

**Поведение:**
- При логине загружается список доступных организаций
- Пользователь выбирает организацию → загружаются мерчанты
- Выбирает мерчанта → загружаются профили
- Можно выбрать "Все профили" для агрегированного просмотра
- Все API-запросы фильтруются по текущему контексту
- Переключение контекста сбрасывает кэш TanStack Query

## 4. Страницы

### 4.1 Онбординг (первый вход)

**Роут:** `/onboarding`
**Условие:** показывается если у текущего мерчанта нет ни одного коннектора.

**Пошаговый визард:**

```
Шаг 1: Создать организацию (если нет)
  ↓
Шаг 2: Создать мерчанта
  ↓
Шаг 3: Подключить первый коннектор (визард)
  ↓
Шаг 4: Настроить маршрутизацию (опционально, можно пропустить)
  ↓
Шаг 5: Провести тестовый платёж
  ↓
✅ Готово — переход на Dashboard
```

Каждый шаг — отдельный экран с прогресс-баром. Можно пропустить (кроме шагов 1-3).

Также на главной (`/overview`) показывается **чеклист-виджет** пока не все шаги выполнены:
- ✅ Организация создана
- ✅ Мерчант создан
- ⬜ Подключите коннектор
- ⬜ Проведите первый тестовый платёж

### 4.2 Обзор (`/overview`)

Главный дашборд с аналитикой. Все данные в контексте текущего Org/Merchant/Profile.

**Фильтр периода:** Сегодня / 7 дней / 30 дней / Квартал / Произвольный (date range picker)

**Карточки метрик (верхний ряд, 4-6 штук):**

| Метрика | Значение | Тренд |
|---------|----------|-------|
| Оборот | сумма ₽ | ↑12% vs прошлый период |
| Успешных платежей | число | конверсия % |
| Неуспешных | число | % от общего |
| Возвратов | сумма | число |
| Средний чек | сумма | тренд |
| Споры | число | открытых |

**Графики (2 ряда):**

Ряд 1:
- **Платежи по дням** — линейный график (успешные / неуспешные / всего)
- **Оборот по дням** — столбчатая диаграмма

Ряд 2:
- **Конверсия по коннекторам** — bar chart (% успешных у каждого коннектора)
- **Распределение по методам оплаты** — donut chart (card 70%, bank 20%, ...)
- **Топ причин отказов** — horizontal bar chart

**Таблица "Последние платежи":** 10 записей, колонки: ID, сумма, статус, коннектор, дата. Ссылка "Все платежи →".

**Чеклист онбординга** (если не завершён) — виджет в правом верхнем углу.

### 4.3 Платежи

#### 4.3.1 Список (`/payments`)

**Фильтры (панель над таблицей, сворачиваемая):**
- Статус — мульти-select (requires_payment_method, processing, succeeded, failed, cancelled, expired, requires_capture, partially_captured)
- Коннектор — select
- Валюта — select
- Сумма — от / до (числовые инпуты)
- Дата — date range picker
- Capture method — select (automatic / manual)
- Поиск — по ID платежа (pay_*)

**Таблица:**

| Колонка | Тип | Сортировка |
|---------|-----|------------|
| ID | ссылка `pay_*` | — |
| Сумма | форматированная (100.00 ₽) | да |
| Валюта | badge | — |
| Статус | цветной badge | да |
| Коннектор | текст + иконка | — |
| Клиент | ссылка или "—" | — |
| Capture method | badge (auto/manual) | — |
| Попыток | число | — |
| Дата | relative + absolute tooltip | да |

**Пагинация:** 20 записей, кнопки Назад/Вперёд + номера страниц. Выбор кол-ва на странице (20/50/100).

**Экспорт:** кнопка "Экспорт CSV" — выгрузка с текущими фильтрами.

#### 4.3.2 Детальная (`/payments/:paymentKey`)

**Шапка:**
- ID платежа крупным шрифтом + кнопка копирования
- Статус — цветной badge
- Кнопки действий (контекстные):
  - **Capture** — если `requires_capture`. Диалог: ввод суммы (по умолчанию amount_capturable), поддержка partial capture
  - **Cancel** — если статус позволяет. Диалог подтверждения с предупреждением
  - **Refund** — если `succeeded` или `partially_captured`. Диалог: сумма (по умолчанию amount_received - уже refunded), причина (optional)

**Информация (grid 2 колонки):**

| Левая колонка | Правая колонка |
|---------------|----------------|
| Сумма / Валюта | Коннектор |
| Net amount | Клиент (ссылка) |
| Amount capturable | Return URL |
| Amount received | Описание |
| Capture method | Authentication type |
| Session expiry | Дата создания |
| Expires on | Cancellation reason |

**Секция "Попытки оплаты":**
Таблица: #, коннектор, статус (badge), сумма, connector_transaction_id (monospace + copy), код ошибки, сообщение, дата.

**Секция "Возвраты":**
Таблица: ID (ссылка ref_*), сумма, статус (badge), причина, коннектор, connector_refund_id, дата.

**Секция "Метаданные":**
JSON-viewer (collapsible tree), кнопка "Копировать JSON". Скрыта если metadata пустой.

**Секция "Ошибка":**
Alert (красный) с error_code и error_message. Скрыта если ошибки нет.

**Секция "Timeline":**
Хронология событий платежа: создан → подтверждён → попытка #1 (failed) → попытка #2 (succeeded) → captured. Вертикальная timeline с иконками и timestamps.

### 4.7 Коннекторы (`/connectors`)

#### 4.7.1 Список

**Карточная сетка** (не таблица — как в Hyperswitch):

Каждая карточка:
```
┌─────────────────────────────┐
│  [Stripe Logo]   🟢 Активен │
│  Stripe                      │
│  mca_abc123...   [copy]      │
│                              │
│  Методы: 💳 Card, 🏦 Bank   │
│  Режим: 🟡 Test             │
│                              │
│  [Настроить]  [⋮ Меню]      │
└─────────────────────────────┘
```

Меню (⋮): Редактировать, Включить/Отключить, Удалить.

**Кнопка "Подключить коннектор"** → визард.

#### 4.7.2 Визард подключения коннектора

Пошаговая форма (multi-step):

```
Шаг 1: Выбор коннектора
  → Карточки: Stripe, CloudPayments, Test
  → Описание каждого, поддерживаемые методы оплаты

Шаг 2: Реквизиты подключения
  → Типизированные поля в зависимости от коннектора:
    Stripe: API Key, Webhook Secret
    CloudPayments: Public ID, API Secret
    Test: (ничего не нужно)
  → Кнопка "Проверить подключение" (валидация credentials)

Шаг 3: Настройка методов оплаты
  → Multi-select: card, bank_account, ...
  → Toggle: тест-режим

Шаг 4: Привязка к профилю (optional)
  → Select бизнес-профиля или "Все профили"

→ Готово: карточка нового коннектора появляется в списке
```

#### 4.7.3 Редактирование (`/connectors/:connectorKey`)

Полная страница с теми же полями что в визарде, но предзаполненными. Кнопка "Сохранить".

```
│  По умолчанию: [Stripe ▾]               │
└─────────────────────────────────────────┘
```

**Volume Split:**
```
┌─────────────────────────────────────────┐
│  Распределение трафика:                  │
│  Stripe        [====████████===] 60%     │
│  CloudPayments [====████=======] 40%     │
│  [+ Добавить коннектор]                  │
│                                          │
│  ████████████████████████████████████    │
│  ^^^^ Stripe 60% ^^^^ CloudPay 40%      │

```

### 4.11 Тестовый платёж (`/test-payment`)

Форма для создания тестового платежа прямо из дашборда.

**Поля:**
- Сумма (number input, по умолчанию 10000 = 100.00)
- Валюта (select, по умолчанию RUB)
- Метод оплаты (select: card)
- Тестовые данные карты (предзаполнены: 4242 4242 4242 4242, 12/30, 123)
- Capture method (toggle: auto/manual)

**Кнопка "Провести платёж"** → создаёт и подтверждает платёж через API.

**Результат:** карточка с результатом (статус, ID платежа — ссылка, сумма, коннектор). Кнопки: "Ещё один платёж", "Посмотреть детали".

**Тестовые сценарии** (preset-кнопки):
- ✅ Успешный платёж
- ❌ Отклонённый платёж (спец. сумма или карта)
- 🔄 Платёж с 3DS

## 5. Общие UI-компоненты

### 5.1 Статус-бейджи (цветовая схема)

| Статус | Цвет | Пример |
|--------|------|--------|
| succeeded | зелёный | `bg-green-100 text-green-800` |
| failed | красный | `bg-red-100 text-red-800` |
| cancelled | серый | `bg-gray-100 text-gray-800` |
| expired | серый | `bg-gray-100 text-gray-600` |
| processing | синий | `bg-blue-100 text-blue-800` |
| pending | жёлтый | `bg-yellow-100 text-yellow-800` |
| requires_* | оранжевый | `bg-orange-100 text-orange-800` |
| manual_review | оранжевый | `bg-orange-100 text-orange-800` |
| active / enabled | зелёный | |
| disabled / revoked | красный | |
| test | фиолетовый | `bg-purple-100 text-purple-800` |
| live | красный | `bg-red-100 text-red-800` |

### 5.2 DataTable (переиспользуемый компонент)

На базе TanStack Table:
- Сортировка по клику на заголовок (серверная, через query params)
- Пагинация (серверная, cursor-based или offset)
- Фильтры (панель над таблицей, сворачиваемая)
- Пустое состояние с иконкой и текстом
- Loading-скелетон при загрузке
- Выбор записей (checkboxes) для bulk-действий
- Адаптив: на мобильных — карточки вместо строк
- Выбор кол-ва на странице (20/50/100)

### 5.3 Формы

- React Hook Form + Zod валидация (клиентская) + серверные ошибки из API
- Кнопка Submit с loading-состоянием (disabled + spinner)
- Диалоги: закрытие по Escape и клику на overlay
- Toast-уведомление (Sonner) после успешного действия
- Inline-ошибки под каждым полем

### 5.4 Подтверждение опасных действий

- Диалог: "Вы уверены? Это действие необратимо."
- Для особо критичных (удаление мерчанта, отзыв ключа): ввести название ресурса для подтверждения
- Кнопка красного цвета, loading-состояние

### 5.5 Копирование в буфер

- Иконка копирования рядом с ключами, ID, URL
- Tooltip "Скопировано!" на 2 секунды
- Monospace шрифт для всех ключей и ID

### 5.6 JSON-viewer

- Collapsible дерево для metadata, webhook payload, connector details
- Подсветка синтаксиса
- Кнопка "Копировать JSON"
- Максимальная высота с прокруткой

### 5.7 Форматирование

- **Суммы:** amount в минорных единицах → основные: `12345` → `123,45 ₽`. Разделитель тысяч — пробел (`1 234,56 ₽`)
- **Даты:** относительные ("5 мин. назад") + абсолютные в tooltip ("18.03.2026, 14:32:01")
- **Ключи и ID:** monospace, кнопка копирования, truncated с tooltip для длинных

### 5.8 Empty States

Каждая страница с пустым списком показывает:
- Тематическая иконка
- Заголовок ("Пока нет платежей")
- Подсказка ("Проведите первый тестовый платёж")
- CTA-кнопка (ссылка на создание / тестовый платёж)

### 5.9 Error States

- Ошибка загрузки данных: иконка + текст + кнопка "Повторить"
- 401/403: редирект на логин
- 404: страница "Не найдено"
- 500: страница с текстом ошибки

## 8. Нефункциональные требования

- **Desktop-first:** корректное отображение от 1024px. Мобильная версия (>375px) — sidebar в sheet, таблицы в карточки
- **Производительность:** серверная пагинация и фильтрация. TanStack Query для кэширования и дедупликации запросов. Lazy loading страниц (code splitting по роутам)
- **Доступность:** keyboard navigation, aria-labels, focus-visible, screen reader support
- **Состояния:** loading (skeleton), empty state, error state — для каждой страницы и каждого блока данных
- **Темизация:** light/dark/system, все компоненты корректны в обеих темах
- **Безопасность:** XSS protection (React по умолчанию), CSRF (Sanctum), не хранить секреты в localStorage
- **i18n-ready:** тексты через константы/файлы (не захардкожены), готовность к добавлению английского языка
