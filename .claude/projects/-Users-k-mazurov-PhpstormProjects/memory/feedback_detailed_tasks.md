type: feedback
---

При создании задач/историй пользователь ожидает подробные, детально расписанные планы имплементации, а не короткие однострочные описания.

**Why:** Короткие описания бесполезны для имплементации — нужен полный контекст, пути файлов, примеры кода, пошаговые инструкции.

**How to apply:** Каждая задача должна содержать: полный контекст, список файлов для создания/изменения, примеры кода, зависимости, критерии приёмки с деталями. Писать как implementation plan, а не как заголовок.
